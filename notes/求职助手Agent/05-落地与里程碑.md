### 本地备份和还原

备份和删除记录保存在访问受限的目录。删除记录每行一个已彻底删除的 `user_id`，独立于待还原的备份，按账号 UUID 重放。同一个邮箱重新注册会获得新 UUID。本地可在手动清理前记下到期账号的 UUID，确认清理完成后写入记录。原库仍可访问时，可以比对原库与还原库的账号 UUID，核对旧备份多出来的账号。合成演练可把两份文件放在 Git 忽略的 `.cache/account-recovery/`。正式备份启用前仍需决定保留期，并让自动清理同步维护一份独立的删除记录。

1. 在仓库根目录用当前开发库生成备份。`pg_dump` 失败时不使用产生的归档。

   ```bash
   umask 077
   mkdir -p .cache/account-recovery
   docker --context colima compose exec -T db sh -c \
     'pg_dump -Fc -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
     > .cache/account-recovery/before-delete.dump
   ```

2. 为还原新建隔离数据库 `jobpilot_restore`。此时应用仍指向原库，或者处于停机状态。`createdb` 返回数据库已存在时选择另一个新库名，并同步修改后续命令。

   ```bash
   docker --context colima compose exec -T db sh -c \
     'createdb -U "$POSTGRES_USER" jobpilot_restore'
   docker --context colima compose exec -T db sh -c \
     'pg_restore --exit-on-error --single-transaction --no-owner --no-privileges -U "$POSTGRES_USER" -d jobpilot_restore' \
     < .cache/account-recovery/before-delete.dump
   (cd jobpilot && POSTGRES_DB=jobpilot_restore uv run --locked alembic upgrade head)
   ```

3. 核对备份之后的删号记录。还原库可能带回已清理账号，也可能缺少后来发起的删除申请。用仍可访问的源库或最新可信记录核对这些账号的 `deletion_requested_at`，保留其实际申请时间和恢复决定。无法确认记录覆盖整个备份间隔时，还原库继续隔离。下面的命令在还原库重放已彻底删除的 UUID，并使备份里所有旧 session 失效。命令中途失败时修正后重跑。

   ```bash
   (
     set -e
     while IFS= read -r user_id; do
       docker --context colima compose exec -T db sh -c \
         'psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d jobpilot_restore -v user_id="$1"' \
         sh "$user_id" <<'SQL'
   DELETE FROM user_account WHERE user_id = :'user_id'::uuid;
   SQL
     done < .cache/account-recovery/purged-user-ids.txt
     docker --context colima compose exec -T db sh -c \
       'psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d jobpilot_restore -c "DELETE FROM user_session"'
     POSTGRES_DB=jobpilot_restore uv run --project jobpilot python -m jobpilot.scripts.purge_accounts
   )
   ```

4. 核对删除 UUID 及关联记录均已消除，再用 `POSTGRES_DB=jobpilot_restore` 启动后端。演练时只绑定本机单独端口。检查旧 Cookie 返回 401、被删账号原密码无法登录、被删业务资源返回 404，并用仍应存在的账号登录核对资料。核对完成后才能切换服务并开放登录。

**2026-11-25 演练结果。** 用独立 Compose 项目创建两个合成账号，每个发布一条事实。备份后申请删除其中一个，仅在演练库把申请推进到期，手动清理删除 1 个账号。旧备份还原到 `jobpilot_restore` 后，SQL 查到该账号和旧事实各 1 条。重放删除 UUID 后各为 0 条，并撤销备份中的 2 条旧会话。最后启动隔离 API，旧 Cookie 和被删账号登录返回 401，被删事实返回 404，对照账号重新登录后可读原事实。复跑清理删除 0 个账号。演练使用合成数据与独立端口。

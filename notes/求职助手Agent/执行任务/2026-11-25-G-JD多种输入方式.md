# 任务 G：添加岗位支持粘贴、文件、截图三种方式（复用简历导入）

日期：2026-11-25。基准：`main` 最新提交。**要在任务 F 的第 3、5 项之前做完**（F 会改同样的 `JobsPage.tsx` 和 `ResumeImport.tsx`）。

## 背景

[01 F2](../01-功能设计.md#f2-jd-解析v1) 规定 JD 输入有粘贴文字和上传截图两种：招聘 App 里的 JD 经常不能复制。现在岗位库的「添加岗位」弹窗（`web/src/pages/JobsPage.tsx` 的 `AddJobModal`）只有一个粘贴框。

能复用的东西都已经有了，只是被做成了「简历专用」：

- 后端：`services/parsing.py` 的 `extract_text`（TXT、Markdown、HTML、DOCX、PDF）和 `ocr_pages` 本来就是给简历和 JD 共用的（模块文档字符串写的就是「简历和 JD 文件」）；`POST /api/ocr` 与业务无关。只有文件提取挂在 `POST /api/resumes/extract` 下，名字是简历的。
- 前端：`web/src/pages/profile/ResumeImport.tsx` 里「粘贴 / 上传文件 / 上传截图 → 文字显示在文本框里让用户核对 → 提交」这一段和简历无关，只有提交那一步（`resumes.upload`）是简历的。

用户希望 JD 和简历一样支持多种格式，并且复用现有实现，不复制一份。

## 开始前必读

1. 仓库根目录 `CLAUDE.md`：**先找现成的**、不复制粘贴后小改；**提交要小**；行为整理和行为修复分开提交。
2. [01 F1](../01-功能设计.md)「输入」和「多张截图的整理」、F2「输入」；[03 可信安全与隐私](../03-可信安全与隐私.md)第 2 节（识别出的文字和粘贴的文字一样是不可信数据，JD 的注入检测照常）。
3. 现有代码：`jobpilot/api/resumes.py` 的 `extract`、`jobpilot/api/ocr.py`、`jobpilot/services/parsing.py`、`web/src/pages/profile/ResumeImport.tsx`、`web/src/pages/JobsPage.tsx`、`web/src/api/endpoints.ts`。

## 要做的

### 1. 后端：文件提取改成通用接口（行为不变的整理，单独提交）

- 把 `POST /api/resumes/extract` 挪成和 `/api/ocr` 并列的通用接口，例如 `POST /api/extract-text`，放进 `api/ocr.py` 或新的 `api/text_import.py`（两个接口都是「把上传的文件变成文字，不保存」，放在一起）。错误码和提示语不变；提示里的「请改用 /api/ocr」保留。
- 旧路径直接删掉，不留别名（只有本项目前端在用）。
- 跟着改：`test_facts_api.py`、`test_isolation.py` 里的路径；`02` 第 6 节接口表；`数据库设计.md` 里提到这个路径的地方。

### 2. 前端：抽出共用的「文字来源」组件（行为不变的整理，单独提交）

- 从 `ResumeImport.tsx` 抽出一个组件（例如 `web/src/components/TextSourceInput.tsx`）：三种来源切换、文件读取、截图识别、可编辑的文本框、读取中状态和出错提示。它只负责「得到用户核对过的文字」，不知道文字拿去干什么。
- 调用方传入的只有文案（例如「点击或拖入简历文件」/「点击或拖入 JD 截图，可以多张」、文本框占位文字）；文件类型、截图张数上限这些和用途无关的常量放在组件里，只写一次。
- `ResumeImport.tsx` 改为用它，外观和行为不变；现有的 `ResumeImport.test.tsx`（重试复用幂等键、成功后换新键）照样通过。
- `endpoints.ts` 里 `resumes.extract`、`resumes.ocr` 挪成通用的（例如 `textImport.extract`、`textImport.ocr`），不再挂在 `resumes` 下。

### 3. 添加岗位用这个组件（行为变化，单独提交）

- `AddJobModal` 换成 `TextSourceInput` 加原来的提交。弹窗加宽到能放下上传区（约 720px）。
- 提交按钮文案用动词：「解析岗位」。截图或文件读出来的文字必须先显示在文本框里，用户看过、可以改，才能提交（01 F2：整理好的文字让用户核对修改，确认后再解析）。
- 截图按上传顺序拼接（自动排序 `order_ocr` 是 P1，和简历一样还没做），提示文字写明这一点。
- 识别出的文字照常走 `POST /api/jobs`，注入检测不变：写一条测试，含可疑指令的文字经这条路径进来，`injection_flags` 照样有值（后端已有的测试覆盖了就写明是哪条，不重复写）。
- 前端测试：选「上传截图」后识别结果进入文本框；文本框为空时不能提交；提交失败保留输入；同一次重试复用幂等键（和简历导入一样）。

### 4. 文档

- `01` F2「输入」加上「上传文件（TXT、Markdown、HTML、DOCX、PDF）」，写明和简历共用同一套读取，原文件不保存。
- `06`：在「前端完整版（任务 A）」那一行之后记一行完成情况。

## 怎么实测

- 自己起一套服务：后端 `uv run --project jobpilot uvicorn jobpilot.main:app --port 8003`，前端 `JOBPILOT_WEB_PORT=5183 UVICORN_PORT=8003 pnpm --dir web dev`。
- 合成测试账号在 `.cache/ui-review/creds.json`（不要写进提交和回报）。合成 JD 用 `evals/datasets/jds/jd-example-001.txt`；截图自己把这份 JD 用浏览器打开后截 2～3 张（可以故意乱序），文件用同一份内容另存成 DOCX 或 PDF。
- 浏览器验收：三种方式各添加一个岗位，解析出的岗位名、要求和粘贴方式一致；乱序截图时文本框里的顺序可以手动调整后再提交；简历导入的三种方式回归一遍。真实模型调用（JD 解析）会产生少量费用，三种方式各一次即可。

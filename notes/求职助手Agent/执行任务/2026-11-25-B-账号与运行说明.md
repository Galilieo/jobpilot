## 要做的

### 1. 申请删除与恢复

- `DELETE /api/account`：记录 `deletion_requested_at`，注销该用户全部登录 session（包括当前这个），把该用户 `running` 的运行标为 `cancelled`。同一事务完成。重复申请不报错、不改变原来的申请时间。
- `POST /api/account/restore`：在申请时间加 7 天之内可以恢复，清空 `deletion_requested_at`；到期返回 409（说明已过恢复期）。待删除账号可以登录，但登录后只能调用恢复、登出、`GET /api/me`（`/api/me` 要返回待删除状态和截止时间，前端据此显示恢复页）。
- **运行取消的竞态**：后台改写运行在保存结果时已经通过 `finish_run` 核对终态，`cancelled` 也是终态，晚到的结果不会写入。写一个测试确认这一点（参考 `jobpilot/tests/test_tailoring_graph.py::test_run_finished_elsewhere_writes_nothing`）。

### 2. 彻底删除（清理任务）

- 找出申请超过 7 天的账号，逐个删除；删除依赖级联（检查每张业务表到 `user_account` 的外键确实是 `ON DELETE CASCADE`，`model_call` 按 02 第 5.3 节匿名保留）。
- LangGraph 检查点：改写流程现在**没有**启用检查点（`run_tailoring` 编译图时不传 checkpointer），所以暂时没有检查点要清。在代码注释和 02 第 5.3 节写明：启用检查点时要先按 `thread_id` 清掉再删账号。
- 后端启动时执行一次，之后进程内每天一次（不引入任务队列）；另提供手动命令 `uv run --project jobpilot python -m jobpilot.scripts.purge_accounts`，打印删除数量。中途失败下次还能找到并重试。
- 测试：待删除期间除恢复、登出、`/api/me` 外的接口都被拒绝（在 `test_isolation.py` 里加一类检查，遍历全部接口）；彻底删除后用任何接口都查不到该用户的数据；恢复后数据完整。

### 3. 导出全部数据

- `GET /api/account/export`：返回一个 JSON 文件（附件下载），包含账号邮箱、全部事实库版本和事实、草稿、简历原文、岗位与个人修改、匹配报告、定制简历的全部版本（含渲染好的 HTML，可用 `services/resume_export.render_html` 的导出模式）。不包含密码哈希、session、模型调用记录里的内部字段。
- 测试：导出内容齐全；跨用户拿不到；待删除账号也能导出（删除前最后取回数据）。

### 4. 账号设置页（前端）

- `web/src/pages/AccountPage.tsx`（替换现在的占位页）：登录邮箱、退出登录、导出全部数据、删除账号（二次确认，写清「7 天内可恢复，之后彻底删除且无法找回」）。
- 待删除状态：`AppShell` 读到待删除状态时，不显示业务页面，显示恢复页（截止时间、恢复账号、退出登录）。

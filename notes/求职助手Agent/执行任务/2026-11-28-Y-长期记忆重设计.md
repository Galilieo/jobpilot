# 任务 Y：长期记忆重设计

日期：2026-11-28。基准：`main` 最新提交。状态：程序验收通过。替换[任务 Q](./2026-11-26-Q-记忆与上下文压缩.md) 第 5 节「长期记忆」的设计；Q 的上下文压缩部分不变。

## 背景

任务 Q 把长期记忆做成 7 个固定栏目（目标方向、城市、排除类型、其他、语气、每条长度、技术名写法），写入要确认卡。用起来有三个问题：

1. **能不能记住取决于关键词。** `services/memory_words.py` 用 `data/memory_keys.yaml` 的栏目别名和操作词（「以后」「加上」「改成」……）判断原话是否授权了这次写入。「我不投外包公司」「我想找 Agent 应用开发的实习」都记不下来，要说「排除里加上外包」才行。每遇到一种新说法就要补一个词，是 CLAUDE.md 说的「特例越加越多，修的层次不对」。
2. **结构化只对三项有用。** 只有写作三项被程序读取（改写时转成固定措辞句）。目标方向、城市、排除、其他只是整块放进对话上下文，程序不用；固定栏目没有带来好处，反而限制了能记什么。
3. **界面像设置表单。** 「我的 → 记忆」一上来 7 行「未设置」，看不出 Agent 记住了什么、从哪来。`source` 存了来源对话，界面没显示。

00 第 4 节把长期记忆标为「深做」，现在的实现撑不起这个说法。

**借鉴的**：字符预算代替条数（Hermes）；会话开始冻结快照（Hermes、Claude）；记忆分类里有一类是「对 Agent 的要求」（Claude Code 的 feedback）；写明哪些不记（Hermes、Claude Code）；自动写入加可见、可撤销（Claude、Hermes）；完全相同的条目拒绝、满了交给 Agent 合并（Hermes）。

**不同的**：写入的依据必须是用户本轮原话（产品底线：经历不能借记忆混进来，JD 里的注入不能触发写入）；会被程序读取的偏好放进结构化的求职条件和写作偏好，而不是记忆文本（LangMem 的 profile / collection 划分）。

## 用户决定（2026-11-28）

1. 写入从确认卡改为**自动写入，对话里显示「已记住」并可撤销**。
2. 目标方向、意向城市放进**求职条件**（事实库），匹配报告用意向城市比对 JD 的工作地点；V2 岗位推荐用它排序。
3. 排除的岗位或公司类型作为**常驻记忆**短句。
4. 表：写作三项改名为 `writing_preference`，每个用户一行；新建的记忆条目表叫 `memory`。
5. 长期记忆**不用 RAG**，全部注入；RAG 用在跨对话搜索，见[任务 Z](./2026-11-28-Z-跨对话搜索.md)。

## 设计

### 1. 三层

| 层 | 放什么 | 怎么进上下文 | 谁用 |
| --- | --- | --- | --- |
| 个人档案（结构化） | 求职条件：目标方向、意向城市、每周到岗天数、实习月数、最早到岗；写作偏好三项 | 求职条件由读取工具取，写作偏好随记忆块注入 | **程序**：匹配比对地点和到岗条件，改写读写作偏好 |
| 常驻记忆 | 用户说过的偏好短句、对 Agent 的要求 | 每段对话开始时全部注入（冻结快照） | 模型 |
| 按需提取 | 事实库、岗位、简历、当前对话原文（已有读取工具）；其他对话（任务 Z）；V2 的弱项与面经 | Agent 判断需要时调用工具 | 模型 |

划分标准：**会被程序读取的放结构化字段；几乎每轮都用得上、而且短的常驻；量大、只偶尔有用的按需取。**

### 2. 求职条件新增两项

- `target_direction` 目标方向：文字，≤ 100 字，存 `text_value`。
- `preferred_cities` 意向城市：列表，≤ 5 项，每项 ≤ 20 字，去重并保留顺序。`fact_set_criterion` 新增 `list_value JSONB`，CHECK 按 `field` 限定只有这一项可用。
- 和现有三项一样走草稿 → 发布，来源为「用户补充」，在「我的 → 经历」的求职条件卡片编辑。
- V1 不改简历抽取：抽取「求职意向」「意向城市」会改变解析行为，需要重跑 E1，列入后续。
- V1 对话里没有写求职条件的工具（`propose_fact` 未实现）。用户在对话里说「我只看上海」时，Agent 说明这属于求职条件，给出入口链接，**不写成记忆**。

**匹配报告的地点比对**（`services/criteria_match.py`，纯函数）：

| JD `location` | 意向城市 | 结果 |
| --- | --- | --- |
| 包含任一意向城市 | 已设 | 符合 |
| 写了城市，但都不在意向里 | 已设 | 「地点不在意向城市」，只提示 |
| 为空，或「多地 / 全国 / 远程」这类无法判断的写法 | 已设 | 待核对 |
| 任意 | 未设 | 不比对 |

地点只是提示，**不计入硬性要求、不改变覆盖判断、不进改写**。「多地」等写法放进 `data/criteria_rules.yaml`，不写在代码里。

### 3. 写作偏好：`writing_preference`

- 每个用户一行：`user_id`（主键）、`tone`、`bullet_length`、`tech_terms`（可空，空表示默认）、`revision`、`source`、`updated_at`。
- 每列的取值约束由 `db/memory_schema.py` 现有的 `WritingChoice` 常量生成（随文件改名为 `db/preference_schema.py` 或保留原名，实施时按引用多少决定，不两处各写一份）。
- 改写读取方式不变：改写运行建立时把三项固定到 `ai_run.writing_preferences_json`，再由程序转成固定措辞句。
- 对话里修改用 `set_writing_preference(field, value, quote)`，规则同下面的记忆写入；`value` 只能是枚举值或 `null`（恢复默认）。原来的口语说法表（「朴实一点」→ 平实）删除，由模型把原话映射到枚举，写入后用户看得到、可以撤销。

### 4. 常驻记忆：`memory`

**每条记忆**：

| 字段 | 说明 |
| --- | --- |
| `memory_id` | UUID |
| `user_id` | 归属，账号删除时级联 |
| `category` | `job_pref` 求职偏好、`agent_rule` 对 Agent 的要求；V2 加 `weakness` |
| `content` | 一句话，1～200 字 |
| `source` | `{"kind": "manual"}`，或 `{"kind": "conversation", "conversation_id", "message_id", "quote"}` |
| `revision` | 每次修改、删除、撤销加一，乐观锁 |
| `created_at`、`updated_at`、`deleted_at` | 删除只打标记，供撤销 |

- **预算**：一个用户全部有效条目的 `content` 合计不超过 `MEMORY_BUDGET_CHARS = 1500` 字符。数据库约束管不了跨行合计，由写入服务在锁住该用户（`SELECT … FOR UPDATE` 锁 `user_account` 行）的事务里检查。
- **去重**：同一用户、同一类别里，有效条目的 `content` 去掉首尾空白后不能完全相同（部分唯一索引 `WHERE deleted_at IS NULL`）。重复写入直接返回「已存在」，不报错（Hermes 的做法）。

### 5. 写入

**新工具类别「自动记录」**（`ToolCategory.RECORD`）：写入但不出确认卡。执行时在同一事务里写数据，并插入一条状态为 `executed` 的 `agent_action`（带 `undo_json`），所以撤销沿用现有的「撤销上一次改动」。属于这一类的只有 `remember`、`forget`、`set_writing_preference`。

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `remember` | `category`、`content`、`quote`、`replaces`（可选，已有条目 ID） | 新增；带 `replaces` 时是改口，替换那一条 |
| `forget` | `memory_id`、`quote` | 删除一条 |
| `set_writing_preference` | `field`、`value`、`quote` | 改一项写作偏好 |

**程序检查**（不通过就返回错误给模型，不写入）：

1. `quote` 必须在**本轮用户消息正文**里逐字出现一次以上，不能来自附件、摘要或历史；本轮正文被 `parse_jd` 当作 JD 来源时一律拒绝（沿用现有规则）。这一条挡住 JD 和历史里的注入，也让删掉的记忆不会被旧对话重新写回来（防重建）。
2. `replaces`、`memory_id` 必须是本人有效的条目。
3. 长度、类别、枚举合法；同类完全相同的内容视为已存在。
4. 超出预算时返回错误，附上现有条目（ID、类别、内容），模型应提议合并或请用户删减，而不是丢弃新内容。
5. 每次运行最多写入 `MEMORY_WRITES_PER_RUN = 3` 次。

**取消关键词绑定**：删除 `services/memory_words.py` 和 `data/memory_keys.yaml`。任务 Q 用它们证明「原话授权了这个动作、这个栏目和这个值」（第四轮评审 [02]）。现在改为：来源检查保证依据是用户本轮说的话；内容由模型概括，**是否忠实于原话靠「可见 + 可撤销」兜底，并由 E8 测量**。这是有意的取舍：自动记录的错误代价低（不进简历、一键撤销），关键词表的代价是大部分正常说法记不下来。

**不记什么**（写进工具说明和系统提示词）：

- 经历、技能、成果 → 应该进事实库，Agent 提示用户补充事实；
- 求职条件（目标方向、城市、到岗、实习时长）→ 提示到求职条件里设置；
- 岗位信息、任务进度、一次性的要求（「这份简历先别导出」）→ 不记；
- 敏感信息（健康、家庭状况、政治、宗教等）→ 默认不记，用户明确要求才记。

**对话里怎么显示**：工具步骤显示「已记住：不投外包公司」并附原话「你说的『我不投外包』」和撤销按钮；`forget`、`set_writing_preference` 同理。

### 6. 进上下文

- 第 2 块「长期记忆」包含：写作偏好三项（有设置的）和全部有效记忆，按类别分组，每条带短 ID（供 `replaces`、`forget` 引用），仍包装为数据块。
- **冻结快照**：对话第一次运行时把渲染好的记忆块存到 `conversation.memory_snapshot_json`，之后同一段对话的每次运行都用这份快照；**压缩时刷新**（压缩本来就会改变前缀）。效果：
  - 提示词前缀稳定，和 02 第 11.3 节「前缀哈希只估算新增后缀」一致；
  - 本对话里刚写的记忆，模型从工具结果就能看到，不需要刷新快照；
  - 在「我的 → 记忆」页面改的内容，从下一段对话（或本段压缩后）起生效，页面上写明。

### 7. 界面

**我的 → 记忆**：

- 卡片一「写作偏好」：三项用分段按钮直接选，带「默认」选项；改写会用到这里，页面写明。
- 卡片二「记忆」：
  - 空状态：「在对话里说出你的偏好或对我的要求，我会记下来；也可以手动添加。」
  - 按类别分组列出，每条显示内容、来源（「来自《对话标题》· 11-28」，可跳转到对话；手动添加的显示「手动添加」）、编辑、删除；
  - 顶部显示用量「已用 420 / 1500 字」，超过 80% 时提示整理；
  - 手动添加：选类别、填内容。
- 原来的目标方向、城市移到「我的 → 经历」的求职条件卡片。工作台的偏好概览同步调整。

### 8. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/memories` | 有效条目、用量与上限 |
| POST | `/api/memories` | 手动添加 |
| PUT / DELETE | `/api/memories/{memory_id}` | 修改、删除，带 `expected_revision` |
| GET / PUT | `/api/writing-preference` | 读取、修改，带 `expected_revision` |

求职条件沿用现有草稿接口，新增两个 `field`。账号导出包含 `writing_preference` 和 `memory`。

### 9. 迁移

一个迁移完成，同一事务：

1. 旧表 `memory` 改名为 `memory_legacy`；
2. 新建 `writing_preference`，从旧表的 `tone`、`bullet_length`、`tech_terms` 三行（未删除的）合并成每用户一行，`revision` 从 1 开始，`source` 取最近一次修改的那行；
3. 新建 `memory`，把旧的四个求职栏目转成 `job_pref` 条目：`目标方向：…`、`意向城市：上海、杭州`、每个排除类型一条 `不考虑：…`、其他偏好原文（超过 200 字按句切成多条）；`source` 沿用旧值；
4. `fact_set_criterion` 加 `list_value`，扩充 `field` 的 CHECK；
5. `conversation` 加 `memory_snapshot_json`；
6. 删除 `memory_legacy`。

迁移不直接写求职条件：求职条件只追加、要经草稿发布，迁移里伪造一个版本风险大于收益。本人库里现有的「目标方向：AI Agent 研发」「意向城市：上海、杭州」会先变成记忆条目，验收时由用户到求职条件里设置后删掉这两条。降级只恢复写作三项和能对应回栏目的条目，其余丢弃，在迁移说明里写明。

## 验收

### 程序测试

- 写入：原话不在本轮正文、来自附件、本轮正文是 JD 时都拒绝；`replaces` / `memory_id` 不属于本人时拒绝；超预算返回现有条目；同类重复返回已存在；每次运行超过 3 次拒绝。
- 撤销：`remember`（新增、替换）、`forget`、`set_writing_preference` 都能撤销，修订号前进；撤销与页面修改并发时一方得到 409。
- 冻结快照：同一对话第二次运行不读新记忆；压缩后刷新；新对话读到最新记忆。
- 改写隔离（E8 门槛）：改写输入里只有写作偏好三项的固定措辞句，记忆条目一个字都不出现。
- 地点比对：上表四种情况，各写法的「多地」规则来自 yaml。
- 隔离：新接口和工具加入 `test_isolation.py` 的遍历清单。
- 迁移：用现有数据形态（含已删除的栏目）升级、降级、再升级。
- 变异检查：至少改坏「原话来自本轮正文」「预算」「快照」「改写不读记忆」四处，确认有测试失败。

### E8 长期记忆（真实模型，在任务 AB 里跑）

2026-11-28 调整：真实模型评测移到[任务 AB](./2026-11-28-AB-Agent行为评测批次.md)，和 E12、E13 端到端共用一套多会话运行脚本。本任务只交付上面的程序测试；下表是 AB 建 E8 数据集时用的场景清单。

20 个多会话脚本，开发、测试各 10，场景：

| 场景 | 通过标准 |
| --- | --- |
| 隐式偏好（「我不投外包」） | 记下，内容忠实于原话 |
| 对 Agent 的要求（「回复短一点」） | 记为 `agent_rule`，下一段对话遵守 |
| 改口（「其实外包也行」） | 用 `replaces` 或 `forget`，不新增矛盾条目 |
| 删除后在新对话里提起旧话题 | 不重新写回 |
| 经历类内容（「我还做过压测」） | 不进记忆，提示补充事实 |
| 求职条件类（「我只看上海」） | 不进记忆，引导到求职条件 |
| 敏感信息 | 默认不记 |
| 超出预算 | 提议合并，不丢弃新内容 |
| 跨会话召回 | 下一段对话的建议用到了记忆 |
| 记忆不进改写 | 门槛，程序测试保证 |

指标：各场景通过率、内容忠实率（人工判断记下的内容是否是原话的意思）、误记率（不该记却记了）。数据集、预期和运行都在任务 AB。

### 本人体验路径

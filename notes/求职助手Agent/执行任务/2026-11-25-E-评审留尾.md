- 新增服务端动作，例如 `POST /api/tailor-runs/{run_id}/resume/bullets/{bullet_id}/use-facts`，带 `base_version_id`。在锁内核对基准（过期 409），按这条条目**服务端保存的原引用**组装文字，新增一个版本；客户端只给条目 ID，不给文字和引用。
- 组装方式和改写回退时一样（`services/tailoring.py` 的 `fallback`：只用这次事实库版本里有效的事实，用 `FALLBACK_SEPARATOR` 连接）。把这段拼接抽成两处共用的函数，不复制。

### 2. 运行的停止原因和终态按固定配对约束

现在 `ck_ai_run_stop_reason`（迁移 `20261124_02`）只要求有停止原因时运行已结束，允许 `succeeded + rewrite_failed` 这种矛盾组合。正常写入路径不会写出这种组合，但以后维护代码写错时，查询页会同时显示成功和改写失败。

- 新迁移把约束收紧为：`service_restarted`、`match_failed`、`rewrite_failed` → `failed`；`budget_exhausted` → `budget_exhausted`；没有停止原因时保持现有允许的终态。
- 配对只定义一次：`services/tailoring_store.py` 已有 `_STATUS_OF`，把它挪到运行模型旁边成为公共常量，代码和迁移都从这里取（迁移里写死当时的值并注明出处，迁移不能依赖会变的代码）。
- 升级前先查现有数据有没有违反新约束的行：有就让迁移报错并打印行数，不悄悄改数据。
- 测试：每种合法组合能写入；`succeeded + rewrite_failed` 这类组合被数据库拒绝；升级、回退、再升级，`alembic check` 无差异。

### 3. 读简历时不再载入全部历史版本的正文

现在 `resume_versions.load_resume` 每次都把这份简历**所有**版本连同 `content_json` 一起查出来，读当前版、预览、导出都这样。自动保存一秒一次，用得越久，每次读取搬运的旧正文越多。

- 整理（单独提交，行为不变）：历史列表只查版本 ID、版本号、创建时间；被选中的那一版另外查正文。调用方需要历史列表的继续拿得到，接口返回不变。
- 测量（单独提交）：在测试库里造一份 200 个版本的简历，比较改动前后读当前版、预览、导出的耗时，用 `EXPLAIN ANALYZE` 看历史列表和单版本查询的计划，据此决定要不要补索引（先看现有唯一键 `(user_id, resume_id, version)` 够不够用）。数字和结论记进 `数据库设计.md` 的 `resume_version` 一节，要补索引就单独一个迁移提交。

### 4. 预览页字体只接受固定选项，并加内容安全策略

现在 `ResumeStyle.font` 接受任意 60 字以内的字符串，模板原样写进 `style="--font: …"`。用户文字的其他路径都有转义，但这里可以写进预期以外的 CSS。

- 字体改为**代码**：`default`、`pingfang`、`yahei`、`source_han`、`songti`、`kaiti`，对应的字体串放 `jobpilot/data/resume_fonts.yaml`（显示名和 CSS 字体串）。服务端按代码映射成固定字符串再渲染；编辑器的字体列表从页面内嵌数据读，不在 `resume_editor.js` 里再写一份（现在约 264 行的 `FONTS`）。
- 旧版本的 `content_json` 里存的是字体串：读取时把已知的字体串映射回代码，认不出的按默认字体处理；不改历史数据。
- 预览页响应加 `Content-Security-Policy`：脚本只允许本页内嵌的编辑器脚本（用 nonce 或 hash），连接只允许同源（保存要用），不允许外部资源。导出的离线 HTML 不加（离线文件要能在本机打开编辑）。
- 测试：任意字符串作为字体被拒绝（422）；旧字体串能读回对应代码；预览响应带这个头。浏览器实测加了 CSP 之后编辑、自动保存、导出、打印、重置都还能用，控制台没有 CSP 报错。

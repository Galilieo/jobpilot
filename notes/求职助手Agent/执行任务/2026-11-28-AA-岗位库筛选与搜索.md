# 任务 AA：岗位库筛选与搜索

日期：2026-11-28。基准：`main` 最新提交。状态：设计已定（2026-11-28 用户同意方向），待实施。**排在[任务 Y](./2026-11-28-Y-长期记忆重设计.md) 之前**；与 Y、[Z](./2026-11-28-Z-跨对话搜索.md) 互不依赖。

## 背景

01 F10 和 07 第 6 节原本就设计了「按方向、技术关键词、城市、进度筛选，标签旁显示数量」。2026-11-23 为了赶 MVP，岗位库只做了列表和详情，现在只有一个「进度」下拉框。岗位多起来之后，找一个岗位要一张张翻。

现状：

- `GET /api/jobs` 返回全部岗位，每项有标题、公司、地点、薪资、到岗、学历、技术关键词、匹配摘要，字段已合并用户修改（`field_overrides_json`）。大部分筛选前端就能做。
- 技术关键词已按 `data/tech_keywords.yaml` 统一写法，带类别。
- **没有「方向」字段**：JD 解析结果里没有「AI 应用 / 后端 / 前端」这类归类。
- **城市写法不统一**：「上海·徐汇」「上海·浦东」「上海」，还有「北京/上海」「多地」。

## 设计

### 1. 方向：程序按规则归类

- 新文件 `data/job_directions.yaml`，每个方向登记标题里的词和技术关键词。示意：

  ```yaml
  - name: AI 应用
    title_words: [AI, 大模型, LLM, Agent, 智能体, AIGC]
    keywords: [RAG, LangChain, LangGraph, LLM, Prompt Engineering]
  - name: 后端
    title_words: [后端, 服务端, Java, Go, C++]
    keywords: [Spring Boot, FastAPI, Django, Gin]
  - name: 前端
    title_words: [前端, Web]
    keywords: [React, Vue, TypeScript]
  ```

  实际词表以开发时的岗位为准，`keywords` 用 `tech_keywords.yaml` 的标准名，加载时校验存在。
- 规则：**先看标题**，命中几个方向就归几个；标题一个都没命中，再看技术关键词，命中最多的那个方向；都没命中归「其他」。只看标题是因为「AI 应用开发实习生」的关键词里常有 Python、FastAPI，按关键词会同时被归进后端。
- 纯函数 `services/job_facets.py` 的 `job_directions(title, keywords) -> list[str]`，列表接口按请求现算，不存库：规则改了，旧岗位立刻按新规则归类。
- 不让模型在解析 JD 时判断方向：那会改变解析行为，要重跑 E2；规则透明、不花钱。

### 2. 城市：归一

- 新文件 `data/cities.yaml`：城市名列表（先放常见的四五十个），以及「多地」「全国」「远程」这类写法。
- `job_cities(location) -> list[str]`：按 `/`、`、`、`，`、`或` 拆开，每段取「·」「-」「市」之前的部分，在城市表里匹配；能识别的归成城市名，「多地」类归为「多地」，其余归「其他」。
- 同样放在 `services/job_facets.py`，列表接口现算。
- 任务 Y 完成后，城市筛选加一个「只看意向城市」开关，读求职条件里的 `preferred_cities`。

### 3. 搜索

- `GET /api/jobs` 增加可选参数 `q`（1～60 字）。服务端在已加载的本人岗位里过滤：标题、公司、地点、技术关键词（合并用户修改后的值）或 JD 原文包含 `q`，忽略大小写和全半角（复用 `services/keywords.py` 里 `_key` 的归一规则，改成公开函数，不另写一份）。
- 不用数据库全文检索，也不用向量：岗位是几个到几十个，在 Python 里过滤就够，结果可预期。按经历推荐相似岗位是 V2 的事。
- 前端输入停顿 300ms 后请求；其余筛选都在前端对返回结果做，**数量随搜索结果变化**。

### 4. 列表接口新增字段

`JobSummary` 加 `directions: list[str]`、`cities: list[str]`。

### 5. 界面

- 顶部一行：搜索框（占位「搜岗位名、公司、技术或 JD 原文」）；筛选：方向、城市、技术、进度，下拉多选，选项后显示数量（「后端（3）」）；技术只列出现次数最多的 15 个；右侧排序：最近更新（默认）、最近添加。
- 已选条件在筛选行下面显示成可单独删除的标签，加「清除全部」。
- 筛选条件写进地址栏参数（`?q=&direction=&city=&tech=&stage=&sort=`），从岗位详情返回时保留。
- 没有结果：「没有符合条件的岗位」加「清除筛选」。
- 卡片本身不变。

### 6. 不做的

- 薪资筛选和按薪资排序：「8k–10k/月」等换算成元/天要另写规则和测试，延后（07 原本就标为 P1）。
- 按匹配情况排序。
- 分页（岗位多到上百再做）。
- 公共岗位切换（V2）。

## 验收

- `job_directions`：标题命中、多个方向、标题未命中回退到关键词、都未命中归「其他」；yaml 里的关键词不在同义词表时加载报错。
- `job_cities`：「上海·徐汇」「北京/上海」「上海市浦东新区」「多地」「全国」「远程」、空值、未知城市。
- 接口：`q` 能搜到标题、公司、关键词、JD 原文；用户改过的字段按改后的值搜；搜不到别人的岗位（加入隔离清单）；`q` 超长返回 422。
- 前端：各筛选组合、数量随搜索变化、地址栏参数在返回后保留、清除全部、空结果。
- 变异检查：改坏「标题优先」「城市拆分」「按改后的值搜索」三处，确认有测试失败。
- 本人验收：用现有 6 个岗位试搜索、按方向和城市筛选。
- 后端三项检查和前端 `format:check`、`lint`、`test`、`build` 全部通过。

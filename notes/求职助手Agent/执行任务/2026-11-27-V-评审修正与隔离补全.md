## 阶段一：用真实 JD 之前必须修的

### 1.1 导出复用旧数据读取（01）

`services/account_export.py` 渲染每个版本时改用 `ResumeContent.from_stored()`，归档里的原始 `content_json` 不变。全仓搜一遍其他读取库里 `content_json` 的地方，如果还有直接用 `model_validate` 的，一并改掉，并在回报里列出。

测试：账号里同时有旧字体（空串、旧 CSS 字体串）和新字体代码的版本，整包导出返回 200，HTML 用映射后的字体。

### 1.2 摘要的要求以原句为准（02，任务 Q 第 3 节）

根因：校验只证明引文的字符出现过，不能证明结论和原话的意思一致。改法：

- 引文必须是来源里一个**完整的短句**，不能只是短句里的一截。来源按句号、问号、感叹号、分号、逗号和换行切成短句，引文要和其中一句或相邻几句完全一致，忽略首尾空白。「接受外包」不是「我不接受外包」里的完整短句，所以通不过。
- 渲染给模型的「要求」一栏，**正文用原句**，模型写的 `statement` 只作为补充说明放在括号里，或者干脆不渲染。原句里的否定和条件就这样原样保留。
- `goal`、`done_and_decided` 是模型写的，程序核实不了，渲染时标题注明「模型概括，未核实」，和「要求」分开。能从数据库读到的已执行动作（已确认的卡片结果），由程序生成，不靠模型写。
- 切短句的函数写成纯函数，放在 `work_summary.py` 或单独的小模块里，不要和别处的分句逻辑重复；先搜有没有现成的。

测试，先写会失败的：

- 原文「我不接受外包」，引文「接受外包」，结论「用户接受外包」，应进入未核实区；
- 原文「北京或上海都可以，但不去深圳」，引文取整个短句能通过，取「去深圳」不能通过；
- 渲染出的「要求」正文是原句。

### 1.3 幂等键退役，不删除（03、07）

根因：删除业务结果时把幂等键一起删了，键的「只生效一次」就失效了。改法：

- `idempotency_key.status` 增加 `retired`。删除投递、删除岗位时，不再删除对应的成功键，改成标记为 `retired`，同时清空 `response_status`、`response_body`，保留 `request_hash`。CHECK 约束同步更新：`retired` 和 `failed` 一样不带响应。
  - 这是表结构和迁移，单独一个提交。
- `claim()` 遇到 `retired` 的键：请求体相同，返回 410，提示「这条记录已经删除，如需重新记录请重新提交」；请求体不同，返回现有的冲突结果。前端拿到 410 时显示这句话，不再重试。前端每次新操作都会生成新键，不受影响。
- 删除旧快照的函数 `delete_result_snapshots` 改名为能说明「退役」的名字，岗位删除、投递删除，以及其他调用它的地方都改过来。
- `claim()` 里的 `.one()` 改为显式处理行不存在的情况（账号删除这类时序仍可能删掉键）：返回稳定的冲突，不再抛异常。
- 账号彻底删除仍然删除全部键，不受影响。

测试：

- 创建投递 → 删除 → 用同一个键、同一个请求体重送，返回 410，没有新投递，也没有新的阶段记录；
- 解析 JD 建岗位 → 删除岗位 → 原键重送，返回 410，不再调用模型（假上游计数为 0）；
- 在领取查询之前删掉键（用测试里的暂停点或直接在同一测试里删行），返回冲突，不报 500。

### 1.4 截断不切开敏感片段（04，03 第 3.2 节）

根因：先截断、再脱敏，截出来的半截邮箱、半截手机号匹配不到规则。改法：

- 在 `llm_gateway.py` 旁边提供一个函数，返回一段文字里所有敏感片段的位置，和 `redact_pii` 共用同一组正则，不另写一份。
- 截断和分页时，如果切点落在某个敏感片段中间，切点往前挪到片段开头。用到的地方有 `compact_input.py` 的预览和 `history.py` 的分页；全仓搜其他「截一段原文发给模型」的地方，一并处理。
- 本地保存和归档仍然是完整原文，游标仍然按原文计。

测试：合成邮箱和手机号正好跨在预览上限、分页边界上，外发内容（经过网关脱敏之后）里没有邮箱或手机号的任何片段，下一页从片段开头接着读。

### 1.5 每日额度（清单三）

现在每一轮有上限，但没有按账号、按天的总上限；反复开新对话会一直累积费用。

- 在网关「发送前登记」那一处加每个账号每日的 token 预扣上限，所有用途共用，按服务器本地日期计算。默认值写进 `config.py` 并有名字，初值 **3,000,000 token/天**（按 DeepSeek Flash 价格约十元以内，2026-11-27 用户已确认；可在 `.env` 改）。
- 超出时，这次调用不发送，返回明确的错误：「今天的模型额度已用完，明天会恢复；可在 .env 调整 DAILY_TOKEN_LIMIT」。对话里显示这句话，运行按失败结束。
- 统计用 `model_call` 已有的登记行和预扣量，不新增表，查询走现有索引 `ix_model_call_user_id_created_at`。
- 账号彻底删除后，`model_call.user_id` 会被清空，这不影响当天额度的统计：账号已经没了。

测试：把额度调到很小，第二次调用被拒，且没有向假上游发送。

**阶段一验收**：以上测试全部先失败后通过；全量 `uv run pytest -q`、`ruff check`、`ruff format --check .` 通过。阶段一合并后升级开发库，提醒用户重启后端。

## 阶段二：应该改的

每一条都先写一个能重现问题的测试。写不出来，说明评审的场景不成立，在回报里说明，不改代码。

- **2.1 入口和窗口同一口径（05 后一半）**：发消息接口的长度检查改成调用窗口估算的同一函数，超出时在入口直接返回 422，提示「这条消息和附件太长，请拆开发送」。前一半（必须缩 20%）不改：估算本来就有误差，只缩一点很可能再被拒一次，白花一次调用。
- **2.2 锁顺序（06）**：列出涉及岗位、对话、定制简历三者的写入路径，包括岗位删除、简历卡确认和撤销、对话岗位绑定，统一加锁顺序（建议：对话 → 岗位 → 简历），写在 `db/` 的模块说明里。做不到统一的地方，照投递创建的做法，用 `NOWAIT` 或锁超时返回可重试的 409。用两个并发事务的测试验证不会死锁。
- **2.3 出卡节点先查再付费（08）**：恢复时，出卡节点先用稳定的工具键查已经保存的候选，命中就直接用，不再调用模型。预扣和实际用量的差额暂不释放，记在回报里，留给统一评测后的费用调整。
- **2.4 旧提问卡答案（09）**：复用现有的旧答案转换函数，读取数组格式的旧答案；关键词筛选基于 JSON 里实际的文本值，和分页层用同一个匹配函数。
- **2.5 全日制、统招（11）**：在 `criteria_rules.yaml` 里把「全日制」「统招」这类本地没有数据的限定词列为「需核对」，程序遇到时不判为已覆盖，交给待核对。规则放在数据里，不在代码里写特例。补一个只满足学历等级的反例。改完用 E3 开发集跑一次程序层（不调模型），结果记进 `evals/README.md`。
- **2.6 投递对比（12）**：
  - 简历条目对比复用导出的可见性规则（`resume_export.py`），没有进入实际投递 HTML 的条目不参与风险提醒；
  - 风险比较加上会改变依据强度的结构化字段，至少包括职责程度；
  - 拆分、合并照旧按新增和删除报，不猜配对。
- **2.7 降级说明（13）**：只写注释，见上文。
- **2.8 「最新简历」统一排序（14）**：写一个函数决定一个岗位的「最新定制简历」，Agent 任务状态、岗位改写列表、投递默认版本、对比的「之后重新生成过」都调用它，按**简历生成完成的时间**排序。用逆序完成的两次改写测试。卡片上除了「第 N 版」，再显示生成日期，方便区分两份简历。
- **2.9 阶段日期（15）**：
  - 服务端拒绝晚于今天的 `occurred_at` 和 `applied_at`（422），日期按服务器本地日期算；

## 阶段三：隔离测试补全（T4.5，清单一）

按[评审报告](./2026-11-27-评审报告-V1后端收尾.md)的清单一逐行补到 `tests/test_isolation.py`，每一行至少一个测试。核心要求：

- 列表和统计类（对话、岗位、事实、定制简历、工作台、投递列表）：A 和 B 都有数据时，只返回调用者自己的数据，包括岗位已删除的投递；
- 组合引用类：A 自己的资源加上 B 的子资源 ID，例如 B 的岗位加 A 的简历版本、A 的对话绑定 B 的岗位、A 的运行加 B 的版本或条目、A 的对话加 B 的确认卡。返回 404，并且断言 B 的数据和数据库里的行**都没有变化**；
- 同名键类（记忆栏目、幂等键、相同 JD 正文）：A、B 各自独立；
- 账号类（导出、删号、恢复、登出）：A 的操作不影响 B；
- **在途删号**：请求通过鉴权之后、写入之前申请删号，写入应失败。投递的修改和删除现在只在入口鉴权，需要在写入事务里复查账号状态，照记忆写入的做法。这一条既是测试，也是代码修复。

能复用的夹具：`test_agent_resume_actions.py`（真实确认卡）、`test_account_archive.py`（A/B 归档）、记忆专项测试。

完成后在 06 把 T4.5 标为完成，并在 `test_isolation.py` 开头写一句：新增接口必须同时在这里登记路由并加 A/B 用例。现有的路由登记测试会对没登记的接口报错，确认它仍然生效。

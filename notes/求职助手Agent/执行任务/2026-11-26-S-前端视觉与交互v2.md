# 任务 S：前端视觉与交互 v2，以及记忆与压缩的前端（T4.1、T3.4 前端）

日期：2026-11-26。基准：`main` 最新提交。

## 背景

任务 P 把对话页接通了，另一个会话按对话页的风格打磨了工作台、岗位库和「我的」。用户试用后觉得有几处交互不对，也有一些地方不够好看，比如：

- 头像菜单展开后箭头不翻转；
- 新对话的输入框沉在页面底部，不明显；
- 每个工具步骤单独占一行；
- 右侧面板叠了三层标签。

规划会话做了[原型 v2](../prototype/v2/index.html)，用户选定**方向 D「雾蓝 + 纸面」**：以 A 为核心，只在少数地方加一点精致感。设计已经写进 [07 前端界面规范第 0 节](../07-前端界面规范.md)。本任务把它落到真实页面上。

## 开始前必读

   - 展开工具步骤；

   原型只用来参照，不复用它的代码；实现用 antd 和 Ant Design X 组件，颜色从主题配置读。
4. 任务书 P 的「实施记录」和留尾。另外看 `web/src/theme.ts`、`web/src/pages/conversation/`、`web/src/pages/job/ResumePanel.tsx`、`ResumeEvidence.tsx`，以及 `jobpilot/templates/resume_editor.js` 和 `web/src/test/resumeEditor.test.ts`。

## 要做的

每一项先写会失败的测试（交互、状态和编号规则），再改代码；纯样式靠浏览器截图验收。

### 1. 主题（一个提交）

- `theme.ts` 按 07 第 0 节和第 2 节调整：
  - 圆角分三级：小控件 5、卡片 8、输入框 14；
  - 核对绿 `#2E6B58` 和浅底 `#EAF3EE`；
  - 阴影按第 0 节的分层写；
  - 等宽数字。
- 宋体大标题用一个共用的样式类，或者一个小组件，字体栈照 07 第 0 节写，**不加载网络字体**。只用在这几处：欢迎语、工作台问候、简历姓名、侧栏 Logo。简历姓名在模板里，见第 4 项。
- 颜色和阴影只写在主题配置或共用样式里，页面里不写零散的颜色值。

### 2. 侧栏和新对话

- 头像菜单展开时箭头翻转，按 Esc 或点外面关闭，用 `aria-expanded` 表达状态。当前页左侧有一条 2px 的雾蓝细线。
- 新对话页：输入框放在欢迎语正下方，带更明显的边框和两层淡阴影。四个入口建议改成输入框下面的一排小按钮，点了把文字填进输入框，不直接发送。输入框下面加一行三个保证：只用你确认过的经历、改动前先问你、每条都能查到依据。
- 发出第一条消息后，输入框回到底部，沿用现有行为。

### 3. 对话页

- **工具步骤按轮合并**：同一轮里的多个工具步骤合成一行，比如「解析岗位、匹配、生成简历，3 步，用时 21 秒」。这句话由步骤的工具名映射成中文动作，再拼起来；映射放在现有的 `naming.ts`，不另建一份。点开后是时间轴，每步一行，后面是耗时。还在运行时，显示当前这一步。
- **确认卡**：照原型 D 的样子：
  - 改前、改后并排，「改成」一侧铺雾蓝浅底；
  - 依据检查在浅绿底上，列出用到的事实编号，编号是白底小块，见第 5 项；
  - 待确认时，卡片带一圈浅色描边，状态前有一个琥珀色小圆点；
  - 确认后变成一行结果和「撤销」，这部分沿用现有逻辑。
- 系统提示（关联、切换岗位）两侧各加一条短线。
- 用户消息的气泡加 1px 细边。

### 4. 右侧面板与简历预览

- **只留一层标签**：简历、匹配报告、岗位。现在简历标签里的「预览与编辑 / 依据追溯 / 底稿没写到 / 版本与运行历史」这一层去掉：
  - 预览和编辑是简历标签的主体；
  - 工具条：「显示依据」开关、一页占用、「更多」、「导出 PDF」；
  - 「更多」里放：依据追溯（逐条列表，沿用 `ResumeEvidence`，用抽屉或弹层打开）、底稿没写到、版本与运行历史、重新生成、全屏编辑。
- **保证条**：简历上方一条绿色保证条，例如「改写 7 条，每条都能追溯到你确认过的事实；没有条目回退到原文」，右侧写「基于事实库 vN」。事实库版本已经落后时，换成 07 第 5.2 节的过期提示。
- **简历预览里显示事实编号**：
  - 改 `jobpilot/templates/resume_editor.js`：外层用 `postMessage` 通知「显示依据：开 / 关」，并把每条的编号和事实原文一起传进去，编辑脚本在每条后面加上编号小块。悬停或聚焦时显示原文。
  - 改过的条目，用淡琥珀色渐变底标出来。
  - **编号只在预览时加**：导出文件、打印、编辑保存的内容里都不能带编号。用现有的 Vitest 编辑器测试来验证这一点。
  - 模板里的简历姓名换成宋体（第 1 项的字体栈）。
  - 这里只改模板里的 JS 和 CSS，不改后端接口。

### 5. 事实编号

- **规则**：每份定制简历里，事实按第一次被引用的顺序编为 F1、F2……。写一个纯函数，放在 `web/src/` 下合适的位置；简历预览、依据追溯、匹配报告标签、确认卡都用它，保证同一份简历里各处编号一致。
- **验收**：
  - 编号顺序稳定；
  - 同一条事实被多条引用时用同一个编号；
  - 切换「显示依据」不改变编号。
- **样式**：绿色实底小块；在绿底上（确认卡的依据检查）用白底加淡绿边；悬停或聚焦时用 antd `Tooltip` 显示「F3 + 事实原文」。
- **对话回复里的纯文本不加编号**：回复是模型写的 Markdown，不能可靠地对应到事实。

### 6. 工作台、岗位库与「我的」

- **工作台**：
  - 问候语用宋体，下面一个输入框：发出后新建对话并跳过去，沿用对话页的发送逻辑，不另写一套。
  - 三个统计并成一条横向的分栏，数字用宋体加等宽数字，每格附一个链接。「记住的偏好」那格读任务 Q 的 `GET /api/memories`，显示已记住的栏目数和简短内容，链接先指向「我的 → 记忆」的占位。记忆页本身归任务 R。
  - 看板：空的列是虚线框，写一句下一步（比如「发一段 JD 就会出现在这里」）；有岗位的列是实底；岗位卡悬停时阴影加深一点。
  - 元信息分开排成小块，不用中点串。
- **岗位库、「我的」**：
  - 按同一套主题统一圆角、阴影和元信息排法，结构不变。
  - 页面标题保持黑体，宋体只用在第 1 项列出的位置。

### 7. 记忆与压缩的前端（T3.4，原计划的任务 R，2026-11-26 并入本任务）

任务 Q 已经提供了后端接口，见[任务书 Q「前端接口」一节](./2026-11-26-Q-记忆与上下文压缩.md#前端接口)。这部分和本任务改的是同一批文件（「我的」、对话页、工作台），所以并在一起做，避免两个会话改同一批文件。

- **接口补字段**（本任务唯一的后端改动，单独一个提交）：
  - `GET /api/memories` 的每一项附上：`label`（中文名）、`type`（文字、列表或枚举）、`options`（枚举的可选值），以及长度和条数上限。这些都从 `jobpilot/data/memory_keys.yaml` 读，前端不再写一份。
  - 只增加字段，不改原有字段和行为。
  - 补后端测试，跑 `uv run pytest -q` 记忆相关的测试文件，以及 `uv run ruff check`。
- **「我的 → 记忆」页**：
  - 按栏目顺序列出七栏，分「求职偏好」和「写作偏好」两组。
  - 编辑控件按类型来：文字用输入框，列表用标签输入，枚举用下拉。保存时调用 `PUT /api/memories/{key}`，带 `expected_revision`。
  - 删除时调用 `DELETE`，同样带版本，并先弹一个二次确认。
  - 返回 409 时，重新读取，并提示「这一栏刚被别处改过，已显示最新内容」。
  - 已删除的栏显示「已删除」，可以重新填写。用户在这里手动恢复是允许的。
  - 页面顶部一句说明：记忆只影响建议和措辞，不会被当作经历写进简历。
- **对话里的记忆确认卡**：
  - `remember` 和 `forget` 用专门的渲染，不再走通用兜底。卡片 `args` 里有 `label`、`op`、修改后的完整 `value`、`quote`。
  - 卡上显示：
    - 栏目名；
    - 动作：增加 / 替换 / 删除几项 / 清空；
    - 修改后的完整值，列表里新增的项高亮；
    - 「来源：你刚才说的『……』」。
  - 确认后的结果行和「撤销」沿用现有逻辑。
- **「压缩上下文」**：
  - 放在对话标题右侧「更多」菜单里，点了弹一个小框，可以填一句重点（≤ 300 字，选填）。
  - 按返回结果分别提示：
    - 202：「正在压缩较早的对话」；如果 `focus_applied` 为 false，补一句「已经有一次压缩在进行，这次的重点没有用上」。
    - 200 且 `not_needed`：「对话还不长，不需要压缩」。
    - 409：「对话正在进行，等这一轮结束再压缩」。
- **工作台**：「记住的偏好」那格读 `GET /api/memories`，显示已填的栏数和简短内容，链接到「我的 → 记忆」。

### 与原型 D 的差异及原因

1. **右侧简历纸面上方保留内嵌编辑工具条**：真实产物接入了 T2.5 `resume_editor.js` 的实时编辑、字体字号、加粗、撤回/前进、A4 分页与自动一页工具条（原型仅作静态展示），外层保留单层工具条与「更多」抽屉，职责分离更清晰。
2. **工作台岗位卡片与岗位库保留薪资、学历 `MetaList`**：后端 `JobSummary` / `BoardJobCard` 已有合并个人修改后的薪资与学历字段，保留显示避免信息损失。
3. **左下角账号头像使用用户图标而非姓氏首字**：后端账号模型无独立姓名字段（仅邮箱），因此沿用通用意象图标与「我的账号 + 邮箱」。
4. **对话记录列表未展示右侧相对日期（「今天 / 昨天」）、助理正文未内嵌原型中的结构化匹配行与追问芯片**：原型用于展示理想交互，真实对话正文来自后端 LLM Markdown 输出，且任务 P 留下的更早决定卡与绑定提示持久化接口不在本次改动范围内。

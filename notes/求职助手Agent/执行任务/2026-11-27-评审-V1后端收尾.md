## 回报格式

按严重程度分三组，组内按重要性排：

- **必须改**：会造成数据错误、越权、数据丢失、费用失控，或者让用户在真实使用时卡住。
- **应该改**：现在不出错，但有明确的出错条件，或者会让后续功能明显难做。
- **建议**：可读性、一致性、更好的做法。

每条按这个格式写：

```
[编号] 标题（一句话）
位置：文件:行号（设计问题写文档名和小节）
场景：什么输入或时序 → 什么错误结果
成熟做法：……（没有可对照的就省略）
建议改法：……
是否已在 06、任务书或数据库设计里记过：是 / 否
```

然后附三张清单：

1. **隔离**：没有被 `test_isolation.py` 覆盖的接口（方法、路径、涉及的资源）；
2. **删号与导出**：没有被删除或导出覆盖的表和列；
3. **费用**：会自动调用模型的路径，各自的上限在哪里。

最后写：

- 你认为设计得好的地方，三条以内，方便用户判断哪些不要动；
- 需要跑测试或实验才能确认的疑点；
- 你没看完的部分。

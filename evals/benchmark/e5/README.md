# E5 简历改写编造率基准

E5 用 10 份合成简历和 5 份合成岗位比较五种改写方式。开发、测试各 25 组，按简历隔离，两组共用 5 份岗位。每份简历的事实、求职条件和教育来自 E1 标注，岗位要求来自合成 JD 标注。原始材料、标注路径和指纹见 [数据清单](manifest.json)。

| 组别 | 改写方式 |
| --- | --- |
| A | 一次模型调用，输入整份简历和岗位原文 |
| A' | A 加事实边界提示词，命令行记作 A2 |
| B | 按经历和技能分块改写并引用事实 ID |
| C | B 加程序检查、修订和回退 |
| D | C 加模型语义检查 |

编造率按含编造的定稿条目占比计算。一条可涉及多个类型。分别用整份简历原文和全量已确认记录评判，分组标题也参与判断。待处理条目单列，仍会保留预算耗尽样本已经定稿的条目。每次启动都计入产出率和成本统计，纯占位【待补】计占位数。七类判据和数据格式见 [裁判提示词](../../prompts/e5_judge.txt)。

## 复现

在仓库根目录执行。按 [JobPilot 本地说明](../../../README.md) 准备 Python、PostgreSQL 和模型服务，应用数据库迁移。评测只向模型发送合成材料。用兼容 OpenAI Chat Completions 的服务跑自己的 A' 时，通过项目已有配置设置 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`JOBPILOT_REWRITE__MODEL_NAME`。模型需接受 JSON Output 和请求里的 `thinking` 参数。下面两种命令分别执行一组样本和完整开发集，结果默认写入 Git 忽略的 `evals/results/`。

```sh
uv run --project jobpilot python -m evals.runners.e5_run --version A2 --split dev --pairs resume-001__jd-syn-01
uv run --project jobpilot python -m evals.runners.e5_run --version A2 --split dev
```

运行五个版本时，相同用途沿用相同参数。匹配和改写/检查各用产品原来的输出上限。正式测试阶段的封存、裁判校准及计分命令见 [评测运行说明](../../README.md#e5-端到端编造率)。评测涉及供应商计费，报告以实际调用记录计算用量。

## 结果适用范围

样本都是面向技术实习的合成材料，测试组也只有五份不同的简历。岗位固定，条目在同一简历或岗位内相关，适合比较这批样本上的差异。A/A' 看原文，B/C/D 看结构化事实并使用匹配、分块和引用，因此 A' 与 B 的差异同时来自输入表示和工作流。B、C、D 使用同一次匹配和同一份初稿。C/D 的差异体现第三层模型检查加入后的效果。
